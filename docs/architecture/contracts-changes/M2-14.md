- **M2-14 (contract):** The HTTPS half of `http_client.rs`, the names it adds to §15.1. `HttpTarget` gains the `Https { host, port }` variant, which needs an egress tag. `HttpRequest` gains `egress: Option<EgressTag>`, and `HttpRequest` is no longer `PartialEq` or `Eq`, because a channel sender is neither. `EgressTag { purpose, subject_id, reports }` is the tag each HTTPS request carries; `EgressReport` (named since M2) is its one report, sent when the connection opens and again every `EGRESS_REPORT_INTERVAL_SECONDS` (5) while the body streams. No new error code: an HTTPS request without its tag is `RRS-N3008` (10.3, already in the catalog), and a certificate the client refuses is `RRS-N2008` with the TLS handshake's own words in `reason`, since the catalog has no TLS code. The TLS tests live in `http_client.rs` because only that file may import rustls, tokio-rustls and webpki-roots (contracts 2.5, `check-imports`).

- §2.5, the rustls row: the crypto provider is `ring`, with the owner's approval of 2026-10-14 (spec v5.4.7). No name or shape changes.
