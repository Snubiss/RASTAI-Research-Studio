- **M1-33:** The offline rebuild of `rastai.db`, `rastai storage rebuild-index`. No wire, document, command, event, table or code shape changes. **Store (15.1):** `rebuild_index`, `RebuildOptions` and `RebuildReport` lose their (M1) markers; the options are `verify_blobs` and `pause_at` (the tests' `RASTAI_TEST_PAUSE_AT` point), the report `runs`, `records`, `artifacts`, `old_index_path` and `diagnostics` (`documents`, `models` and `pruned_run_stubs` arrive with the projects scan, the HF cache scan and the archive stubs that make them, M4, M2 and M11). `COLUMNS_NOT_REBUILT` and `ColumnsNotRebuilt` name the columns no durable source holds, which the row-by-row check skips: `command_journal`'s `arguments_json`, `idempotency_key`, `result_json`, `job_id`, `started_unix_ms` and `arguments_hash` (`command.finished` carries none of them), `runs.project_id` (`run.json` doesn't record the project) and `schema_migrations.applied_unix_ms`; `TABLES_NOT_REBUILT` lists the three tables a rebuild starts empty (13.2). **Moved names (15.1):** `DaemonLogSegment` (now with `segment_number`), `daemon_log_segments` and `daemon_log_name` move from `rastai-server` to `rastai-store`'s `event_log/daemon_log.rs`; `store_error_diagnostic` moves from `rastai-server`'s `error.rs` to `rastai-store`'s; `job_kind_name` moves from `rastai-server`'s `launch.rs` to `rastai-core`'s `states.rs`. Each now has one owner that the daemon and the rebuild share, so both name segments and job kinds alike and both report a `StoreError` with the same message. **New names:** `rastai_db_rebuilding_path` and `runs_dir` in `rastai-core` (15.1) with the path row `<data>/rastai.db.rebuilding` (8.1); `LocalOutcome` and `run_rebuild_index` in `rastai-cli`'s `local_commands.rs` (15.1); the fixture `fixtures/data-dirs/two_runs/` with its README (15.8); the pause points `store.rebuild.after_run_folders`, `store.rebuild.before_swap` and `store.rebuild.before_rename` (15.9). **Crash safety:** the new index is written to `rastai.db.rebuilding`, checked with `quick_check` and left in one file (rollback journal), then the old file is hard-linked (or copied) to `rastai.db.broken-<unix_ms>` and stays at `rastai.db` until the new one is renamed over it, so a kill at any point leaves a whole index; flows/platform.md 6.4's first step ("move rastai.db aside") is done that way. **Live indexing (no shape change):** `submit_job` reads the clock once for `run.json`'s `created_at` and `runs.created_unix_ms`, so a rebuild gives the row the same time to the millisecond.
