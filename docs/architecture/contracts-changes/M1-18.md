- **M1-18 (contract):** ModelSpec v1 for TextCNN. `rastai.model/1` lands as a struct with its description, schema and generated JavaScript and Python types, so its 5.2 row loses its (M1) marker, and 15.1 registers its code names, the op vocabulary's and layer 3's. Shapes this PR settles (5.2): an edge is `{from_node, to_node, to_input}` (`to_input` from 0, only `concat` has more than input 0); an input map entry is `{name, range{start, end}, encoder_node}`, the range in positions of the input sequence with its end left out, and the encoder node takes the input as its input 0; a head is `{name, graph_node}`; `objective.kind` is `classification` until the decoder objectives join (M2-01); `defaults` holds `dtype` (`bf16`/`fp16`/`fp32`), `sequence_length` and `batch_size`, the sizes shapes are worked out with; `weights` is the list of `{source, family, name_mapping, prefix}` the row already named (plan §10 row 11), so M2-01 builds on it rather than settling it; `placement` is graph node id to GPU index, empty for one device. A graph node has `node_id`, `op`, `label`, `attributes`, `train_mode` (`train` by default) and `observe` (true by default); `blocks`, `lora`, `block_ref`, `repeat`, `opaque` and `layout` stay in the rows and join as optional fields with the tasks the rows now name (M2-01, M5-E03, M6-E04, M6-E01), so a file written now still reads then. 5.3 gains the attributes and shape rule of the eight TextCNN ops (`embedding`, `conv1d`, `pool`, `linear`, `dropout`, `activation`, `concat`, `classifier_head`), channels-last (`[batch, length, channels]`, so no transpose op is needed), and the golden file's numbers are for one forward pass over its input shapes, not per token, with the FLOP convention stated: what `torch.utils.flop_counter.FlopCounterMode` counts, 2 per multiply-accumulate of a matrix multiplication or convolution, everything else 0 (the Python compiler's `test_op_fixtures.py` counts with it, python layout 2). Layer 3 reports an op attribute it can't use (missing, unknown, of the wrong kind, a size of 0, a probability of 1 or more) with `RRS-E2006` at the attribute, not layer 2's `RRS-E1xxx`, because layer 3 never blocks loading. One new code, `RRS-E2007` (a graph node input isn't connected exactly once): an op's input fed by nothing, or by two edges or input map entries, which `RRS-E2006` ("isn't in its required form") would describe badly (10.3). 15.8 registers `fixtures/ops/` (with its README) and the template `templates/designs/textcnn.rrsmodel`, the owner's 5-layer TextCNN (AITestLab-1 `create_model.py`) as a ModelSpec, which closes the spike's open exit item "TextCNN ported off torchtext and `.pt`" on the design side.
