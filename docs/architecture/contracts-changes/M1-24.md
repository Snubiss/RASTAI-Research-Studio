- **M1-24:** Event-log frames, reader and writer. `crc32.rs` gets its functions, `crc32` and `update_crc32`, the one CRC-32/IEEE table (7.1). 15.1 registers the code names of `event_log/`: the frame constants and functions of `frame.rs`, `FrameRead`, `open_event_log`, `reader_offset`, `create_event_log`, `open_event_log_for_append`, `append_event`, `sync_event_log` and `truncated_tail_bytes`. The reading rules made exact (7.1, flows/platform.md 6.2): a crash only damages the end of a file, so a bad frame is the torn tail when nothing but zeros follows its start (a power cut can leave a zero-filled block) or, for a checksum mismatch, when nothing but zeros follows its declared end (a power cut can keep a frame's header and zero its body); a frame whose checksum matches but whose body isn't a version-1 `EventRecord` is corrupt; a frame whose declared end overruns the file, or a checksum mismatch with only zeros after it, is the torn tail unless a whole, checksum-valid, version-1 frame with a later sequence lies in the 1 MiB after its header (then it is corrupt: bit rot in its length, not a crash); when the bytes after the header start as the frame's own record, candidates start only where its top-level fields end, so a record whose text quotes a frame can't make its own torn tail read as corruption and block the run's resume; the search runs at most 4 MiB of candidate bodies through CRC-32, so its time is bounded too, and a search that runs out counts the frame as the torn tail. The Rust writer's batched fsync uses the worker's constant, `METRICS_FSYNC_INTERVAL_SECONDS` (15.10). The fixtures are 12.5's plus `sequence_gap.log` (15.8); `event_frame` joins the nightly fuzz matrix. No new codes: `RRS-S2001`–`S2003`; `RRS-S0006`, the store's read code (M1-23 (contract)), for a log that can't be opened or read, so a missing log never reports a failed write, and its 10.3 row now names event logs beside databases (the catalog title still says "Database read failed"; its basic text, "couldn't read its saved data", holds for both); `RRS-S3002` and `RRS-S3005` for writes (10.3).
