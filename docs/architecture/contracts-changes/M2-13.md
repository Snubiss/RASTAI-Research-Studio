- **M2-13:** The model hash (contracts 8.6) is BLAKE3 over the model's tensors (one line per tensor: name as a JSON string, dtype, shape, BLAKE3 of the data bytes; sorted by name; `__metadata__` left out), not over the weight files' names and file hashes. A re-sharded copy of the same tensors keeps its hash, and replays, steering presets, chat-template overrides, lock files and run records keep their identity. Two files holding one tensor name are refused with the new code `RRS-E1007` ("a safetensors layout can't be planned or hashed"), which the caller-misuse refusals of the safetensors planner use too (not `RRS-E1006`, whose text is about JSON map keys); the code is added to the 10.3 seed table, `catalog/errors/RRS-E.json`, the generated catalog and `docs/reference/errors.md`. Layout 4.7 gives the Python binding `model_hash(weight_files: Vec<String>)` (paths, read through `FileSource`, so no whole file is passed in memory), and layout 4.5 and the flow lines that name the model hash (`flows/platform.md`, `flows/training-evaluation.md`, `flows/inference-psychology.md`) agree with 8.6. The folder `content_hash` of a dataset stays a file-level rule. The names this task builds are registered in 15.1 by the task's code PR, not here.
