- **M2-13:** The model hash (contracts 8.6) is BLAKE3 over the model's tensors (one line per tensor: name as a JSON string, dtype, shape, BLAKE3 of the data bytes; sorted by name; `__metadata__` left out), not over the weight files' names and file hashes. A re-sharded copy of the same tensors keeps its hash, and replays, steering presets, chat-template overrides, lock files and run records keep their identity. Two files holding one tensor name are refused with the new code `RRS-E1007` ("a safetensors layout can't be planned or hashed"), which the caller-misuse refusals of the safetensors planner use too (not `RRS-E1006`, whose text is about JSON map keys); the code is added to the 10.3 seed table, `catalog/errors/RRS-E.json`, the generated catalog and `docs/reference/errors.md`. Layout 4.7 gives the Python binding `model_hash(weight_files: Vec<String>)` (paths, read through `FileSource`, so no whole file is passed in memory), and layout 4.5 and the flow lines that name the model hash (`flows/platform.md`, `flows/training-evaluation.md`, `flows/inference-psychology.md`) agree with 8.6. The folder `content_hash` of a dataset stays a file-level rule. The names this task builds are registered in 15.1 by the task's code PR, not here.
- **M2-13 (code):** The names this task builds are registered in 15.1 without a marker: `plan_safetensors` and `read_safetensors_header` lose their (M2) marker, and `TensorPlan`, `SafetensorsLayout` (`safetensors/writer.rs`) and `read_tensor_bytes` (`safetensors/reader.rs`) are new. The reader reads the 8-byte length and then the header with two plain reads, hands the header to `check_safetensors_header` (so every refusal is the one check's `RRS-E60xx` code), and reads tensor bytes only after that, one tensor at a time into the caller's buffer; a source shorter than the header claims is refused with `RRS-E6011` before the buffer grows. The planner settles the header and the offsets: tensors in name order, metadata first with its keys sorted, compact JSON, spaces to 8 bytes, the bytes the Python writer writes for ASCII names. The planner's refusals (a repeated tensor name, a tensor named `__metadata__`, a repeated metadata key, a size or total past 64 bits, a header past `MAX_HEADER_BYTES`, 100 MiB) use `RRS-E1007` from the contract entry above, not `RRS-E1006`. The reader's own `RRS-E60xx` codes stay for files already on disk. `model_hash` reads each tensor in chunks of at most 1 MiB into the stream hasher, so memory is bounded by the chunk, not by the largest tensor; the same hash. No dependency is added; the header is written with `serde_json` values that the crate already uses.
