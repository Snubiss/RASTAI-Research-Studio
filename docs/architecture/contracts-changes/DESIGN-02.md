- **DESIGN-02:** The owner-approved UI design (#266) needs three theme changes, all additive, so `rastai.theme/1` and `rastai.settings/1` keep their version. (1) `rastai.theme/1` gains `typography.font_sizes_px.xxl`, the display size for headings. It is an optional key. An added optional key keeps the version, because every existing v1 file still validates (the same way `ModelSpec` `lora` (M5-E03) was added inside `rastai.model/1`): a file that leaves it out reads as before, and then the display size is `xl`. (2) `rastai.theme/1` gains `colors.confidence_tint`, the shading behind chat text by model confidence. It is a 41st optional color role in a new "Chat" row of the 5.6 table (`COLOR_ROLES` has 41 entries); a role left out falls back to `base`. The two built-in themes set it, because `packages/ui` checks that each built-in sets every role: `light.theme.json` `#fff1c2` and `dark.theme.json` `#4a3b12`. These values are provisional until DESIGN-03 sets the designer's values. (3) The `ui.theme` setting gains the value `high_contrast`, the built-in high-contrast theme (5.6, 11.2). The setting is a plain string, so `settings.set ui.theme high_contrast` already validates; the theme itself and its `--rr-*` values come with DESIGN-03. Existing theme files and fixtures validate unchanged, and so does every stored content hash (`night.theme.json` writes the same bytes, because the new fields are left out when unset). The generated `schemas/rastai.theme/1.json` and `schemas/rastai.settings/1.json`, their `schemas/index.json` hashes, and the generated theme and settings types in `packages/formats` and `python/rastai_formats` change with them. `check-schema-diff` covers commands and events only, so it sees no change here. `check-names` is unchanged, because the new names are fields of a document, not registry names. The CSS variable `--rr-font-size-xxl` is not emitted until DESIGN-03 adds it to `apply-theme.js`.
