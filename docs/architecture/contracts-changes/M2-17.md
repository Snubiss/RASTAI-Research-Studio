- **M2-17 (contract):** `model.download` takes an optional `revision` (a branch, tag or commit; left out for the repository's default branch), so a pinned download reproduces the same files, as `download.finished` already reports the revision (orchestrator decision on issue #73, from the M2-12 review). The field is additive and optional, so `check-schema-diff` allows it and `model.download` stays `preview`. No new name: `ModelDownloadArgs` gains the field, and the 6.4 row and the 15.x row say so.
- **M2-17 (catalog code):** `RRS-N3013` ("Redirect refused: no target, or more than 5 hops") is a refused redirect: a Hub or CDN answer with no `Location`, or one that would take the download past 5 redirects. The downloader fails at once, because the Hub would give the same answer on a retry, so the code is not an interruption and is never retried (orchestrator decision on issue #73, from the M2-17 third review). It is listed in 10.3 and in the `rastai-node` row of 11.1. Its entry is in `catalog/errors/RRS-N.json`, and the generated catalog and error reference are regenerated with `just codegen`. No command or event shape changes in this entry.
- **M2-17 (code names):** The downloader's names, registered in 15.1 (`rastai-transport`: `Sha256`, the incremental form of `sha256_digest`; `rastai-node`: `hf_cache.rs` and `downloads.rs`, listed in the M2-17 names paragraph) and the constants of 15.10 (`HF_LOCK_POLL_SECONDS`, `DOWNLOAD_RETRY_FIRST_SECONDS`, `DOWNLOAD_RETRY_MAX_SECONDS`, `HF_HUB_HOST`, `HF_HUB_PORT`, `HF_HUB_OFFLINE_VARIABLE`, `HF_DOWNLOAD_EGRESS_PURPOSE`). `NodeError` gains the download variants; their codes are the ones 10.3 already lists. No command or event shape changes.
