- **DESIGN-03:** `@rastai/ui` follows the owner-approved design (`docs/design/ui-design.md` §4 and §5). No wire, document, command, event or schema shape changes: the theme file keeps its `rastai.theme/1` shape, and the values in it are data. (1) The built-in `light.theme.json` and `dark.theme.json` take the design's values (roles, `typography.font_sizes_px.xxl` 28, `font_weights.bold` 600, `line_heights.code` 1.45, radius 4/6/10, elevation, the blue/orange `diverging_negative`/`diverging_positive` default, and `colors.confidence_tint` #c75300 light and #f0883e dark), and the font families name Geist and Geist Mono. (2) A third built-in, `packages/ui/src/tokens/high_contrast.theme.json` (`id` `builtin_high_contrast`, `base` `dark`, so it takes the dark locked set), is registered in `built-in-themes.js` under the name `high_contrast`, which `ui.theme` names (5.6, 11.2); `builtInTheme` takes the names `light`, `dark` and `high_contrast` (`BuiltInThemeName`, re-exported from `@rastai/ui`). The file is `high_contrast.theme.json` with an underscore, to match the `ui.theme` value; ui-design.md 9 (c) and 10 write `high-contrast.theme.json`, and that design file (DESIGN-01's) is not changed here. (3) `applyThemeTokens` emits `--rr-font-size-xxl` (xl's value when a theme leaves `xxl` out, filled in by `resolveTheme`). (4) The Geist and Geist Mono variable woff2 files and `OFL.txt` are bundled under `packages/ui/src/fonts/` (15.8, with a README of the source release and checksums), loaded by `@font-face` in `styles/base.css`; nothing is fetched at runtime. (5) New names in 15.3: `@rastai/ui`'s `StatePill` (with `StateTone`), `SegmentedControl` (with `SegmentOption`) and `StatTile`, and `@rastai/ui/security`'s `TokenConfirm` (the locked "create token" prompt: the "Rastai security check" header, the title, the "It can" and "It cannot" lists, and after approval the show-once box with Copy). `TokenConfirm` takes `tokenValue` (`string | null`, the new token's value that the settings page passes once `token.create` has run; null before approval, when there is no box, Create token is enabled, and there is no checkbox; Create token is disabled once pressed, until the caller closes the prompt, so a double click cannot approve twice). `TrustPrompt`'s Install is the filled button, as Create token is. Done closes the prompt after approval and is `onCancel`, the same close handler as Escape and Cancel. `SegmentedControl` takes an optional `disabled` prop (every option disabled, nothing presses, and the text is greyed). Their files are `components/StatePill.jsx`, `components/SegmentedControl.jsx`, `components/StatTile.jsx` and `security/TokenConfirm.jsx`, with `security/LockedFocusRing.jsx` (the security UI's focus ring, drawn inside each locked component instead of in `components.css`) and `security/SecurityCheckHeader.jsx` (the "Rastai security check" line with a lock glyph, on `TokenConfirm` and `TrustPrompt`; neither file is exported from `@rastai/ui/security`). `ThemeCard` and `ContextChip` (ui-design.md 5.2) are not built here and are not registered here; the PR that builds each one registers it in 15.3. (6) `components.css` gains the blocks of the three new components and loses the security focus ring, which the security components now draw. (7) `PanelChrome`'s menu takes focus on open, moves with the arrow keys, Home and End, returns focus to its button on Escape or Tab, closes when focus leaves it, and keeps its items out of the Tab order; its keys act only while it is open, so a closed menu never swallows an Escape (M1-51 sweep follow-up, issue #261; the WAI-ARIA menu-button pattern). Existing theme files and fixtures keep validating: `fixtures/documents/rastai.theme/valid/every_role.theme.json` now sets all 41 color roles and `xxl`, and its content hash in `content_hashes.json` changes with it; `night.theme.json` and every other stored hash are unchanged. `check-schema-diff` and `check-names` see no change (the new names are JavaScript exports, and the 15.3 package rows are unchanged). (8) `SegmentedControl` (ui-design.md 5.2) takes the arrow keys, Home and End to move focus between options (the arrows do not press), and makes the group one Tab stop: the option focus last visited inside the group has tabIndex 0, and the pressed option does until focus has been inside, so Shift+Tab after an arrow leaves from the arrowed-to option. Focus leaving the group puts the stop back on the pressed option. The `disabled` prop is in (5). (9) The `contracts.md` §5.6 Chat row now describes `confidence_tint` as what it is in this model: a saturated base hue that the chat mixes into `surface` at 16, 30 and 46% (ui-design.md 4.4), not "the shading behind chat text" (the DESIGN-02 wording). The values are unchanged. The description strings in `schemas/rastai.theme/1.json`, the generated `packages/formats` and `python/rastai_formats` theme types, and `crates/rastai-formats/src/documents/theme.rs` still say "Chat text shading by model confidence."; they are left for a separate change, because the schema's content hash in `schemas/index.json` would change with them and the shape stays the same, so it is not part of this PR.
