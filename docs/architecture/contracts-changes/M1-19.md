- **M1-19:** The rastai-formats wheel. `rastai-formats-python` lands (`crates/rastai-formats/bindings/python/`, the one pyo3 user), so it loses its (M1) marker and lists serde_json, which it writes the answers with (2.1). The module `rastai_formats._native` has `read_document`, `load_model_spec`, `write_document`, `content_hash` and `hash_bytes` and raises `FormatsValidationError`, whose one argument is the diagnostics as a JSON array of the 4.1 fields (15.1); `python/rastai_formats` wraps each in a plain function of the same name that looks the native one up on every call, so M1-34's delegation test can stand in for one (15.2). `check_safetensors_header` (M1) joins from M1-34. Two signatures differ from the layout's sketch (control-plane 4.3 and 4.7), for the owner's review: `document_content_hash` returns `Result<String, FormatsError>`, because serde can in principle refuse a value, and the wheel's `read_document` raises `FormatsValidationError` in that same impossible case instead of returning a string it can't build. `rastai-formats` gains `document_content_hash` (a typed document's hash, its defaulted fields counted, so a file and the same file written back have one hash) and `document_header_mut` (the mutable twin of `document_header`, which a new document type now also adds an arm to), and `write_document` is built (15.1). `Document` serializes as its own struct (`#[serde(untagged)]`). `write_document`, `content_hash` and `load_model_spec` refuse a document with any error, and a newer-version one (read-only, `RRS-E4001`), whose unknown fields they would drop; `load_model_spec` also refuses a valid document of another type with `RRS-E1004` at `/type`, and until M1-18 adds `rastai.model` it refuses every input, which is the truth. `fixtures/documents/content_hashes.json` lists every valid corpus file's content hash, checked by Rust and the wheel (12.5). The wheel is built by maturin 1.15.0, which the cpu lock's dev group pins by hash; the cpu environment builds rastai-formats without build isolation, with that maturin, and `just env-cpu` rebuilds the module on every sync (`--reinstall-package rastai-formats`, a cargo no-op when nothing changed). `.cargo/config.toml` sets `PYO3_BUILD_EXTENSION_MODULE` (15.9) so cargo never links libpython. pyo3 is pinned at 0.29.2; its build dependency `target-lexicon` is `Apache-2.0 WITH LLVM-exception`, which `deny.toml` accepts by name (as the Python allowlist does for torch), and pyo3 and pyo3-ffi join libc's parents.
