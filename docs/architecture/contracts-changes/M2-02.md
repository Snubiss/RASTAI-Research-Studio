- **M2-02 (names, no shape change):** the observation contract and the runtime's per-pass switches. `observation.py` gives the capture modes (`CAPTURE_NO_ATTENTION` "none", `CAPTURE_LAST_TOKEN_ATTENTION` "last_token", `CAPTURE_FULL_ATTENTION` "full") and the `PointHook` and `DecodeReadout` base classes, now built. An observation point is a graph node's output, named by the node's id, so `CompiledModel.point_names` lists them in graph order. `forward_context.py` builds `ForwardContext`. `attention_kernel.py` names the three kernels (`KERNEL_SDPA` the default, `KERNEL_MATH` and `KERNEL_EAGER` for exact replay) and selects one per pass: full attention capture forces eager, as the captured maps are eager's softmax. `model_traits.py` gives `ModelTraits` (has_moe, has_mla, has_alibi, has_attn_res, sliding_node_ids, approximate_lens), read from the spec's ops. The has_* traits and `approximate_lens` read block bodies too; `sliding_node_ids` lists only top-level nodes, because a block body's node has no instance path until block expansion (M2-05) gives one, and its id would repeat across bodies and stamped copies. `ForwardContext` has no `caches` field yet: the KV caches come with M2-04. `forward` and `run_steps` take the context as the keyword `context`, so no caller binds it by position. Both take one input, `input_sequence`, not the `*inputs` of layout 2.2: the multi-input designs that would need it are not built yet, and layout 2.2 gets the change then. The `VARIANT_ATTRIBUTE` constant stays in `compiler/op_table.py`, which `model_traits.py` imports. Every new public name is listed in the rastai_models row of §15.2; the three names marked (M2) there that this PR builds lost their mark. No wire, document or command shape changes.
