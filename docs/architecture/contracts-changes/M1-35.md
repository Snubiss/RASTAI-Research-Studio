- **M1-35:** The ModelSpec compiler and the TextCNN blocks land in `rastai_models` (python layout 2.1), so `compile_model`, `init_weights`, `bind_weights`, `BindReport` and `CompiledModel` lose their (M1) markers in 15.2, and 15.2 registers the code names under them: `compiler/` (`order_graph`, `GraphStep`, `StepInput`, `OP_MODULE_CLASSES`, `NO_VARIANT`, `find_op_module_class`, `implemented_ops`, `apply_train_modes`), `blocks/` (`OpModule` with `init_parameters`, one class per TextCNN op of 5.3), and `CompiledModel`'s `graph_steps`, `op_modules`, `run_steps` and `graph_parameters`. Rules this PR settles inside the layout's design: a parameter's name is its graph path, `<node_id>.<name>` (`conv_1.weight`), and that is the tensor name weight files use; the op modules sit in a `ModuleList` in graph order, not under their node ids, because a node id is any string (5.2) and torch refuses a module name with a dot. The model's input is one `[batch, length]` sequence, and each input map entry hands its range of positions to its encoder node (5.2). Ties in graph order go to the node listed first in the file, so one spec gives one order. A strict fill checks every name and shape before it copies a value, so a refused bind leaves the model unchanged: a parameter without a tensor is `RRS-M2002`, a tensor without a parameter, or one two files hold, `RRS-M2003`, a different shape `RRS-M2004`; an op with no implementation is `RRS-M0001` (10.3, no new code). `train_mode` `lora` freezes the node's base weights; its adapters attach with `lora.py` (M5). Seeded init draws every value on the CPU in float32 from one `torch.Generator`, in graph order, then casts, so a seed gives the same weights on any device and dtype; the distributions are torch's defaults (standard normal embeddings, uniform ±1/√fan_in for weights and biases). Two parts of the layout's interface arrive later, as the layout's build order has it: `CompiledModel.forward` takes the input sequence without a `ForwardContext` (M2), and `bind_weights` takes the model and its files, with the `spec` and `family` arguments joining with `Family` (M2). `SafetensorsFile` gains `shape(name)`, a tensor's shape from the accepted header, so the bind checks shapes without reading tensor bytes. 15.8 registers `fixtures/models/textcnn/expected_counts.json` (with `fixtures/models/README.md`): the template's parameter count, 3,290,692, its trainable count and each node's count, which `test_compile.py` checks and Rust live stats (M6-E02) will too. `test_op_fixtures.py` walks `op_table.py` against `fixtures/ops/`, both ways, and checks each case's output shape, parameter count and FLOPs (counted with `FlopCounterMode`) against the golden file.
