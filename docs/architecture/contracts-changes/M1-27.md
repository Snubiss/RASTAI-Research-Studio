- **M1-27:** The `Execute` path and the L0 floor. `rastai-server`'s command layer lands (`commands/`: `execute.rs`, `dispatch.rs`, `context.rs`, `arguments.rs`, `journal.rs` and the handlers `system.rs`, `command.rs`, `settings.rs`, `token.rs`), so `CommandContext`, `execute_command` and `check_arguments` lose their (M1) markers, and 15.1 registers `dispatch`, `not_available_code` and `IdempotencyKeyLock`, the `Server` fields `registry`, `settings_overrides`, `idempotency_locks` and `http_port`, and the handler files. `execute_command` follows flows/platform.md 3.2 in order: `acting_plugin_id` narrows the principal to the plugin's grant (empty until the plugin host, M1-32), an unknown command is `RRS-C0001` and a retired one `RRS-C0007` with its replacement as the fix, the scope is checked before the arguments (`RRS-C1005`), a plugin's command needs its plugin enabled (`RRS-C0003`), and the arguments go through layer 2 (`RRS-C0002` first, then each `RRS-E` problem with its JSON pointer). A dry run reaches the handler with `dry_run` set and is never journaled; `read`-scope commands aren't journaled either. Every other command gets the journal's started row, then its finished row with the redacted result. An idempotency key seen within `IDEMPOTENCY_KEY_LIFETIME_HOURS` replays the stored, redacted response (a replayed `token.create` answers `<redacted>` and makes no second token), a different command or different arguments under it are `RRS-C0004`, a duplicate sent while the first runs waits for it, and an earlier attempt that failed or was interrupted runs again. Redaction follows 5.1 at any depth (a listed type, a list, a map); text the daemon can't judge, such as a plugin command's arguments before its `types.json` is read (M4), is redacted whole. `dispatch` has one arm per row of `COMMANDS`: the handlers of `system.status`, `system.shutdown`, `command.list`, `settings.get`, `settings.set` and `token.*`, and the L0 stubs, which answer their area's "not available yet" code (catalog/README.md); anything without an arm falls through to the plugin host, `RRS-P1004` for a plugin's command until forwarding lands (M4) and `RRS-C0001` for a core id with no arm. Publishing `command.finished` joins with the bus and the daemon log (M1-28), and a startup now closes the journal rows a crash left unfinished with `RRS-C0005`.
- **M1-27:** The Connect envelopes handed over from M1-26. `http/connect.rs` loses its (M1) marker: `CommandService` is served as Connect unary in `application/proto` and `application/json` (`http/command_endpoints.rs`, `Execute` and `ListCommands`); a gate refusal on a Connect path, and a body that can't be read, come back in the Connect error envelope (`unauthenticated` 401, `permission_denied` 403, `invalid_argument` 400, else `internal` 500) whose one detail is the `rastai.common.v1.Diagnostic`, as base64 protobuf and as JSON in `debug`; a content type the service doesn't take is 415 with `Accept-Post`. A command that fails stays `ExecuteResponse{ok: false}` with HTTP 200. The stream envelope and the end-of-stream envelope that `Subscribe` (M1-28) writes land with it: 15.1 registers `stream_message_envelope`, `end_of_stream_envelope` and `connect_error_json`. prost moves from a dev dependency of `rastai-server` to a dependency, used by `http/connect.rs` only (layout 8.4).
- **M1-27:** Scoped tokens reach the gate. `token.create` makes a token of 32 random bytes as 64 lowercase hex characters, stores only its BLAKE3 hash, and adds it to `AuthState`'s cache (15.1: `ScopedToken`, `add_scoped_token`, `revoke_scoped_token`, `find_scoped_token`), which startup fills from `rastai.db`; a bearer token found there is a `token` principal with exactly its scopes, and a revoked one is `RRS-C1006` on its next request. Closing a revoked token's open streams joins with the streams (M1-28). `rastai-store` gains `list_tokens`, `JournalFinishedRow` with `IndexWrite::JournalFinished` (the finished columns and the redacted `result_json`, which the `command.finished` record doesn't carry), and `write_config_file` (`config_files.rs`, losing its (M1) marker; `StoreError::ConfigFileWriteFailed`, `RRS-S3005`). `rastai-formats` gains `parse_arguments` (losing its (M1) marker) and `result_json`.
- **M1-27:** Settings files join the daemon. Startup resolves the defaults, the user's `settings.json`, then the environment and `--set` layers; a user file that doesn't parse is left out, logged with `RRS-C0009` and never overwritten. `settings.set` writes the user's file, or with `level: project` the `settings.json` in the folder of the project the request names (`ExecuteRequest.project_id`, a `projects` row), checking the whole document first (an unknown key is `RRS-C0002` at `#/key` with `RRS-E1003`, a wrong value `RRS-C0002` at `#/value`); `settings.get` adds the project's layer when the request names a project. No new codes, commands, events, tables or settings.
- **M1-27:** Two fixes from the final security review. A login code is owner-only (6.4, flows/platform.md 4.1): its session runs as the owner, so `token.login_code.create` refuses every other principal with `RRS-C1005` (scope shown as owner), a scoped token or plugin holding `system.admin` and the owner narrowed by `acting_plugin_id` included; before this a `system.admin` token could redeem a code at `POST /api/login` and then create tokens with any scope. And the idempotency check compares a keyed hash of the unredacted arguments instead of the redacted ones, which can't tell two secrets apart: `command_journal` gains `arguments_hash` (8.2; `rastai-store` migration `0002_journal_arguments_hash.sql`, `JournalStartedRow.arguments_hash`, `JournalRow.arguments_hash`), BLAKE3 of the canonical arguments keyed with the owner token's hash, written only for a row with an idempotency key; a different hash, or a row without one, is `RRS-C0004` (5.1). 15.1 registers `arguments_hash` (`rastai-server` `commands/journal.rs`). No new codes, commands, events or settings. The threat model records R27 (`settings.set` keys that become code execution later should be owner-only, M1-32) and R28 (revoking a token doesn't revoke the tokens it made).
