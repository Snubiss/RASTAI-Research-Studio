- **M1-25:** The indexer, the blob store and free space. `apply_event_record` (`indexer.rs`) writes the rows of layout 6.4 for every M1 payload, by upsert or update keyed by ids; the event types without a payload message yet (`transfer.finished`, `download.finished`, `lineage.linked`, `run.deleted`, `archive.*`, `gateway.request_logged`) get their rows with the contract PR that adds the payload. `checkpoint.saved` also writes its `checkpoint_of` lineage row (8.2). `IndexWrite::ApplyRunEvents` and `IndexWrite::ApplyDaemonEvents` apply a batch exactly once: they skip records at or below the ack and commit the rows with `runs.acked_sequence` or `log_cursors.acked_sequence`; the daemon variant carries its segment's `log_name`, since each segment has its own cursor (7.1), and their `handler_calls` arrive with `HandlerCall` (M5). The blob store's names join 15.1 (`BlobStore`, `PutMode`, `put_bytes`, `put_file`, `open_blob`, `has_blob`, `verify_blob`); `open_store` clears `.incoming/` but keeps transfers' `.partial` files (8.4). `free_bytes` and `check_free_space` land in `disk_space.rs` with the workspace's one `unsafe` (ADR-0033); a free space that can't be read is `RRS-S3001`, like one that is too small. `list_table_rows` reads a whole table for the idempotence test and the rebuild's row-by-row check (M1-33). A run's log is untrusted: `ApplyRunEvents` refuses a record that names another run, carries an event only the daemon's log carries (`job.state_changed` among them), takes over another run's checkpoint, names an id of the wrong kind, changes an existing artifact (any column, its time included, or its lineage) or gives a parent a relation outside the artifact ones, and the log counts as damaged there (7.1). One new code, `RRS-S2004`, for that refusal; the others are `RRS-S1001`, `RRS-S1002`, `RRS-S3001`, and `RRS-S0006` now also covers a blob that can't be read (10.3).
