# python/rastai_worker: the job runtime

Read the root `CLAUDE.md` and `python/CLAUDE.md` first. The layout is `docs/architecture/layout/python.md` §7.

- **What is here.** The job process (M1-40): `__main__.py` (a thin main), `arguments.py` (the `run` and `plugin` command lines), `launch.py` (`run_job_process`: the start order below), `job_file.py` (`WorkerLaunch`, `read_job_file`), `worker_server.py` (`WorkerService`: Hello, Control, WatchLive), `host_connection.py` (Register with retry; `HostWatcher` registers again after a node restart), `live_stream.py` (`LiveStream`), `job_events.py` (`WorkerJobEvents`), `control.py` (signals and Control values to `JobControl` flags), `diagnostics.py` (the edge: final records, Diagnostics, exit codes), `exit_codes.py`, `dispatch.py` (`JOB_ENTRIES`) and `plugin_module.py` (plugin mode, a skeleton until HandleCommand, M4). The event log (M1-39): `event_log.py` (`EventLogWriter`, the one writer of a run's `events.log`, and `pause_for_full_disk`), `event_payloads.py` (an engine's `(event_type, dict)` to the typed `EventPayload`, the frame body's encoding, and job.json's `JobSpec`) and `errors.py` (`WorkerError`). The job modules (`jobs/`) and the rest of layout §7.1 arrive in their build steps (§7.11): `jobs/train.py` with M1-46.
- **The start order** (`launch.py`): signal handlers, then job.json and the entry (a bad file or an unknown kind exits 2 before anything is written), then the event log (a held lock exits 5 before Register) and the metrics flusher, then WorkerService on the job socket, then Register (the node calls Hello as soon as Register arrives), then the entry under the edge. Keep it.
- **Job entries** are `run_job(job_spec, host, events, control)` (contracts 12.3). `JOB_ENTRIES` names each kind's entry as `<module>:<function>`, imported only when a job of that kind starts; `eval` and `lens` go through `jobs/plugin_entry.py` (M4), the one place that imports `JobSpec.entry`, so until then they are a bad launch. An entry emits metrics, checkpoints and artifacts and polls `JobControl` between steps; it never writes the final `run.state_changed`: `diagnostics.run_entry_with_diagnostics` does, from how the entry ended (completed, or with reason `stopped` after STOP; cancelled, exit 3; preempted, exit 75; failed with a coded `diagnostic.reported`, exit 1).
- **Handlers only flip flags.** gRPC handler threads and signal handlers never touch the model, the log or the GPU (layout §7.6). SIGTERM sets only `preempt_requested`, SIGINT only `cancel_requested`, SIGHUP is ignored; TERMINATE and KILL are never Control values.
- **Failures are coded.** An error with a catalog code keeps it, torch's out-of-memory error is `RRS-H3007`, anything else `RRS-J1005`; the traceback goes to stderr.log only, never into the log. A job that can't start prints one line, `<code>: <message>`, to stderr (the node reads the last line). A log that can't be appended exits 4; a full disk pauses the run first (`pause_for_full_disk`) and exits 4 only when the pause records fail too. A job asked to end doesn't pause: it frees the reserve and tries once more, and exits 4 only when that fails too.
- **The job token** comes from `RASTAI_JOB_TOKEN`, travels in the `rastai-job-token` metadata key and is never written to a file or a log. `worker_server.py` refuses every call without it (UNAUTHENTICATED).
- **One writer per log.** `EventLogWriter` takes an exclusive `flock` before it reads or writes anything; a second writer fails with `RRS-J3006` before it touches the log or `events.log.reserve`, and its job process exits with `EXIT_EVENT_LOG_LOCKED` (5) without writing the log (python layout 7.5; contracts 9.1, one live job per run). Never write a run's log from another process or another run, and only rank 0 writes it (layout §7.6, §7.8).
- **The bytes are the Rust writer's.** Frames, checksums (`zlib.crc32`) and bodies must equal what `rastai-store`'s writer writes, so `fixtures/event-logs/` is one set of files for both languages. Encode a body only through `event_payloads.encode_message`, never `SerializeToString`: Python's protobuf runtime writes maps differently from prost (default entries, key order). `tests/test_event_log.py` writes `fixtures/event-logs/from_python.log` from a recipe that `crates/rastai-store/tests/python_log_compat.rs` repeats in Rust; change the two together.
- **Recovery follows the Rust reader.** `event_log.py`'s reading half is `rastai-store/src/event_log/reader.rs`'s rules (contracts 7.1) ported line for line, so every file a writer can produce gets the same verdict in both languages (a crafted body whose known field has the wrong wire type decodes in upb and not in prost; see the top of `event_log.py`): a torn tail is cut on open (`truncated_tail_bytes`; the caller reports `RRS-S2001`), corruption is `RRS-S2002`, a gap `RRS-S2003`, and the file is never changed when the open is refused. A change to those rules changes both files and both test suites.
- **Codes.** The log's errors keep the store's codes: `RRS-S0006` (can't open or read), `RRS-S3005` (a failed write), `RRS-S3002` (disk full). Other worker errors use `RRS-J` codes. A wrong argument from calling code (an event type a worker doesn't emit, an unknown payload field) is a bug and raises `ValueError`.
- **fsync policy.** `fsync_now` for state changes, checkpoints, diagnostics and artifacts; metrics are batched and fsynced at least once every `METRICS_FSYNC_INTERVAL_SECONDS`. `WorkerJobEvents`' flusher thread calls `flush_if_due` on a timer, so a quiet job's last metrics don't wait for the next append; the writer isn't thread-safe, so every call into it from `WorkerJobEvents` takes `log_lock`.
- **Only `event_payloads.py` imports the protobuf runtime** (`check-imports`), and only `worker_server.py` imports grpcio (its test, `tests/test_worker_server.py`, too: it calls WorkerService as the node does and serves a fake WorkerHostService). Engines never see `rastai_proto` (layout §1.4 rule 7).
- **POSIX only for now.** `flock`, `pread` and `pwrite` are POSIX; the tests carry the `posix_only` marker and the package isn't in `test-python-portable`. `fcntl` is imported inside the lock function so the package still imports on Windows.
