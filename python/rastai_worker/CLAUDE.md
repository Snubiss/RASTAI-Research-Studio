# python/rastai_worker: the job runtime

Read the root `CLAUDE.md` and `python/CLAUDE.md` first. The layout is `docs/architecture/layout/python.md` §7.

- **What is here (M1-39).** `event_log.py` (`EventLogWriter`, the one writer of a run's `events.log`), `event_payloads.py` (an engine's `(event_type, dict)` to the typed `EventPayload`, and the frame body's encoding) and `errors.py` (`WorkerError`). The job process, `WorkerService`, the host connection, control and the live stream arrive with M1-40; the rest of layout §7.1 in its build-order step (§7.11).
- **One writer per log.** `EventLogWriter` takes an exclusive `flock` before it reads or writes anything; a second writer fails with `RRS-J3006`. Never write a run's log from another process or another run, and only rank 0 writes it (layout §7.6, §7.8).
- **The bytes are the Rust writer's.** Frames, checksums (`zlib.crc32`) and bodies must equal what `rastai-store`'s writer writes, so `fixtures/event-logs/` is one set of files for both languages. Encode a body only through `event_payloads.encode_message`, never `SerializeToString`: Python's protobuf runtime writes maps differently from prost (default entries, key order). `tests/test_event_log.py` writes `fixtures/event-logs/from_python.log` from a recipe that `crates/rastai-store/tests/python_log_compat.rs` repeats in Rust; change the two together.
- **Recovery follows the Rust reader.** `event_log.py`'s reading half is `rastai-store/src/event_log/reader.rs`'s rules (contracts 7.1) ported line for line, so a file gets the same verdict in both languages: a torn tail is cut on open (`truncated_tail_bytes`; the caller reports `RRS-S2001`), corruption is `RRS-S2002`, a gap `RRS-S2003`, and the file is never changed when the open is refused. A change to those rules changes both files and both test suites.
- **Codes.** The log's errors keep the store's codes: `RRS-S0006` (can't open or read), `RRS-S3005` (a failed write), `RRS-S3002` (disk full). Other worker errors use `RRS-J` codes. A wrong argument from calling code (an event type a worker doesn't emit, an unknown payload field) is a bug and raises `ValueError`.
- **fsync policy.** `fsync_now` for state changes, checkpoints, diagnostics and artifacts; metrics are batched and fsynced at least once every `METRICS_FSYNC_INTERVAL_SECONDS` (call `flush_if_due` on a timer when a job may go quiet).
- **Only `event_payloads.py` imports the protobuf runtime** (`check-imports`), and only `worker_server.py` will import grpcio. Engines never see `rastai_proto` (layout §1.4 rule 7).
- **POSIX only for now.** `flock`, `pread` and `pwrite` are POSIX; the tests carry the `posix_only` marker and the package isn't in `test-python-portable`. `fcntl` is imported inside the lock function so the package still imports on Windows.
